# 16 结合个人项目的追问（30 题）

这部分是领导根据你的述职内容最可能深挖的问题，题目来自你迭代文档里的项目。

## 智能体平台
1. agent-mount 优化从 3s 降到 98ms，瓶颈到底在哪？只是查库次数多吗？
2. 改成 `WHERE IN` 批量查询后，挂载项特别多（上千个）时会不会有新问题？
3. 优化后协程数只降了 30%，剩下的协程是什么？还能再降吗？
4. 为什么用双接口加提前 return 灰度，而不是用配置开关？
5. 追问优化只改了 Prompt，如果以后换模型，这套 Prompt 失效怎么办？
6. 追问的 badcase 评估只有 150 条样本，结论可靠吗？怎么扩大评估规模？
7. 240 个智能体的自愈方案，如果千帆重建也失败，会怎样？有没有重复创建的风险？
8. 首 token 慢的根因是历史消息序列错误，为什么历史里会出现没有回复的 user 消息？源头修了吗？

## 商业化线索
9. RFQ 链路跨 5 个服务、5 种通路，你怎么保证字段一个都没漏？
10. 704 必须先上线，如果 704 上线后出问题回滚，其他服务会怎样？
11. 线索组件召回时机怎么判断？召回太频繁影响用户体验怎么办？
12. 会员信息要跨 4 个服务透传，为什么不让 mount 服务自己去查会员状态？

## 数字人
13. 「最近使用」接口为什么选 Redis ZSET 加 MySQL 双写？只用 MySQL 行不行？
14. 双写时 Redis 写成功、MySQL 写失败，数据会不一致吗？
15. 为什么只缓存最近 16 条？这个数是怎么定的？
16. 多人调度的命中统计为什么最后选了 query 维度而不是 session 维度？

## 平台与 PaaS
17. 端到端评估的 Worker 先改状态再处理，如果处理到一半进程挂了，任务会卡住吗？
18. 交叉质检分数按分档合并，为什么不直接取平均？
19. 可用率预先写到 figure 表，什么时候会和实际数据不一致？怎么修正？
20. PaaS 审核状态不落表、实时聚合，查询量大了会不会有性能问题？
21. 交付 stage 只在三处推进，另外还有定时巡检兜底，巡检多久一次？发现不一致怎么处理？
22. 公版从客户层级挪到模板层级，存量数据怎么迁移？
23. 长底板方案复用状态枚举、不新增状态，以后要扩展新状态会不会很难？
24. 「云渲染-长底板」要同步改三处筛选映射，漏改一处就查不到。有没有办法从结构上避免这种问题？
25. 15GB 文件上传，为什么并发 18 比并发 12 还慢？

## 数据治理
26. 20T 对话数据冷备到 AFS，如果以后要恢复某个用户的数据，怎么查？
27. 分批删除时如果删错了，怎么恢复？
28. 删除后为什么还要单独做表空间释放？释放时对线上有什么影响？
